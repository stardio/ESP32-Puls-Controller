# 승인 게이트

대상 게이트: $ARGUMENTS

1. 대상을 정한다. 인자가 없으면 status.md에서 '검토대기' 단계를 찾는다: ②→G2, ③→G3, ⑥→G6. 해당이 없으면 "게이트 대상 아님"을 보고하고 종료한다.
2. `pm-orchestrator`를 호출해 해당 단계의 완결성 점검 결과를 받는다.
3. `templates/gate-record.md` 형식으로 체크리스트를 **출력한다**. 게이트별 핵심 항목은 다음과 같다.
   - G2: 필수 FR/NFR이 측정 가능한지, 원가 목표, 규격·인증, 마케팅 검토 반영, 확인 필요 질문 해소
   - G3: SRS 추적표 커버리지, 대안 비교 근거, MCU·핵심 부품 선정, BOM 원가 대 목표, 수급 위험
   - G6: 미해결 결함, 시험 합격률, 미검증 사양, 문서 완비, 가격 제안과 원가·경쟁가 비교
4. 사용자에게 `승인 / 조건부 승인(조건) / 보류(사유) / 반려(사유)` 중 하나를 묻고 **응답이 올 때까지 멈춘다.**
   이 턴에서는 어떤 기록도 작성하지 않으며, 다음 단계 명령도 실행하지 않는다.
5. 사용자가 응답하면:
   - `project/gates/G2-requirements.md` / `G3-design.md` / `G6-release.md`에 사용자의 결정과 사유를 그대로 기록한다.
   - 승인 또는 조건부 승인이면 확정 항목을 `project/decisions.md`에 D-ID로 추가하고(날짜·결정·근거·게이트), status.md에서 단계를 '완료'로 바꾼다.
   - 보류나 반려이면 사유를 status.md 이슈로 올리고 단계를 '보류'로 바꾼다.
