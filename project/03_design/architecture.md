### 2.3 이더넷(Modbus TCP 서버, HMI 연결)

- 구성 대안
  - **ETH-A: MCU 내장 이더넷 MAC + RMII PHY + 마그네틱스 내장 RJ45.** STM32F407은 MII/RMII 이더넷 MAC(전용 DMA, IEEE 1588v2)을 내장한다[S6]. ESP32(기본형)는 10/100 Mbps 이더넷 MAC(전용 DMA)을 내장하고[S1], ESP-IDF는 내장 MAC에 대해 RMII만 지원한다[S3]. ESP32-P4도 RMII 이더넷 MAC을 내장한다[S5].
  - **ETH-B: SPI 이더넷 컨트롤러(W5500 등) + 마그네틱스 내장 RJ45.** W5500은 하드웨어 TCP/IP 스택, 독립 소켓 8개, SPI 최대 80 MHz, 내부 버퍼 32 KB, MAC·PHY 내장이다[S9]. ESP32-S3처럼 내장 MAC이 없는 MCU는 이 방식이 필요하다[S3](ESP32-S3에 내장 MAC이 없다는 것은 Espressif 컴포넌트 문서의 EMAC 지원 대상 목록에서 빠진 것으로 판단한 간접 근거).
- 비교

| 기준 | ETH-A 내장 MAC + PHY | ETH-B W5500(SPI) |
|---|---|---|
| CPU 부하 | TCP/IP를 MCU 소프트웨어(lwIP 등)가 처리. 펄스 엔진과 CPU·메모리 버스를 공유 | TCP/IP를 W5500이 처리. MCU는 SPI 전송만 함 |
| 동시 접속(NFR-023) | 소프트웨어 설정(메모리 한도) | 하드웨어 소켓 8개가 상한[S9] |
| 지터 위험(NFR-003) | 이더넷 DMA·인터럽트가 펄스 엔진 소프트웨어 개입 지점과 경쟁. 펄스가 하드웨어 생성이면 영향은 "속도 갱신 마감" 문제로 한정 | SPI 전송 중 CPU 점유. 영향 범위는 ETH-A와 같음 |
| 핀 수 | RMII 핀 다수(수는 MCU별 데이터시트 확인, 미확인) | SPI 4선 + 인터럽트·리셋 |
| 원가(정성) | PHY + 마그네틱스 | 컨트롤러 + 마그네틱스. PHY 별도 불필요 |

- 포트 수: 1포트 [가정](HMI 1대 + PC/PLC는 공장 스위치 경유). 2포트(데이지 체인) 필요 여부는 미확인(Q26) → DC-03.
- 이더넷 포트 절연: 마그네틱스(펄스 트랜스)로 절연한다. 요구 절연 내압 값은 IEEE 802.3 원문으로 확인해야 하며 이 문서에서는 **미확인**으로 둔다(NFR-009, §10 이슈 #2).
- 기능 배치: Modbus TCP 서버 1개(포트 502 [가정, Modbus 규격 기본 포트. 규격 원문 대조 전]), 레지스터 맵은 RTU·TCP 공통. 통신 두절 감시(FR-012)는 TCP 연결별 무통신 시간으로 판정한다.

### 2.4 펄스 생성(축당)과 펄스 출력단

- 축당 신호: PULSE, DIR(Step/Dir) 또는 CW, CCW(FR-002). 두 방식 모두 "축당 출력선 2개"이므로 출력단 하드웨어는 같고, 펌웨어가 모드에 따라 펄스를 어느 선으로 낼지 바꾼다.
- 생성 원칙(대안 비교 결과, §4.2):
  1. 펄스 주기와 펄스 폭은 하드웨어 타이머(또는 RMT)가 만든다.
  2. 출력 펄스 수는 하드웨어 카운터가 센다. 이동 종료 시점의 정지도 하드웨어가 결정하는 방식을 우선한다(소프트웨어 인터럽트 지연으로 펄스가 더 나가는 것을 막기 위함. NFR-004).
  3. 가감속은 "일정 주기(예: 수백 µs~1 ms [가정])마다 다음 구간의 주기 값을 갱신"하는 구간 방식으로 한다. CPU 부하가 펄스 주파수와 무관해진다. 구간 갱신 주기·곡선 형상(FR-007 사다리꼴/S자 미확인)은 모듈 설계에서 정한다.
  4. (v0.2 개정) 위치(지령 위치)는 "MCU가 계산한 값"이 아니라 "펄스 타이머 출력을 하드웨어 계수한 값"으로 둔다(FR-004, FR-006, NFR-004). v0.1의 "비상정지 게이트 뒤 되먹임"은 PS-10 추천(AM26C31 enable 직결)과 맞지 않는다. 차동 출력은 enable 뒤 신호를 되읽을 수신기가 없고, 추가 논리 게이트(BOM C11)는 부품·가격 미확인이다. 따라서 기본안은 **비상정지 후 위치 무효 플래그 + 원점복귀 요구**로 하고, 게이트 앞 AND 게이트 출력 계수(위치 유지)안은 DC-08 선택지로 둔다. 리밋·알람·언더런 정지는 하드웨어 게이트를 거치지 않으므로 계수값이 실제 출력과 같다.
- 출력단
  - 차동: RS-422 계열 라인 드라이버(필수, NFR-005(a)). 5 m 배선(NFR-006 [가정]).
  - 24 V 오픈 컬렉터(권장, NFR-005(b)): 축당 별도 트랜지스터 출력단을 두고 단자를 분리한다 [가정]. 24 V 오픈 컬렉터 출력단이 200 kpps를 낼 수 있는지는 소자·배선 용량·풀업 저항에 좌우되어 **미확인**이며 **G3 전 실측 필요**. 불가 시 NFR-005 규정대로 G3에 보고한다.
  - (v0.2) PS-15 결과: 드라이브 측 오픈 컬렉터 입력 한도가 LS L7P 200 kpps(제3자 사양서)[P20], MR-J4-700A 200 kpulse/s(제3자 목록)[P19]로 D-007 하한과 같다. 즉 OC 경로는 드라이브 쪽에서도 여유가 0이며, 200 kpps 초과가 필요한 설비는 차동 경로를 써야 한다. 후보 소자 ULN2003A(달링턴)는 200 kpps 스위칭이 데이터시트로 보증되지 않았다(PS-06, 조건부). → DC-11에서 "OC 경로 보증 상한 ≤ 200 kpps(실측값이 낮으면 실측값)" 사양을 제안한다. OC 실장 시 축당 단자 +2극이 필요하며 BOM A4에 반영되어 있지 않다.
  - 펄스 형식 구현(v0.2): 축 PWM 타이머의 CH1 = PULSE/CW, CH2 = DIR/CCW. Step/Dir 모드에서는 CH2를 강제 출력 레벨로, CW/CCW 모드에서는 이동 방향 채널만 PWM 활성. 출력단 하드웨어는 두 모드 동일(interface-spec §4).

### 2.6 비상정지 경로

```
 비상정지 입력(24 V, 절연) ──┬──► [B-EGATE] 펄스 출력 enable 차단 (하드웨어, MCU 비경유)
                             └──► MCU 인터럽트 → 펄스 엔진 정지 → 상태 '비상정지' 래치
                                                → 해제 명령(Modbus/PC/HMI) 전 기동 거부
```

- 1차 경로(하드웨어): 비상정지 입력이 라인 드라이버 enable(또는 앞단 논리 게이트)을 직접 끊는다. MCU 정지·펌웨어 오류와 무관하게 펄스가 멈춘다. 응답 시간은 절연 소자 + 게이트 전파 지연으로 정해지며 값은 부품 확정 후 산정(**미확인**, NFR-011).
- 2차 경로(소프트웨어): MCU가 타이머를 정지하고 상태를 래치한다(FR-010 재기동 금지). 해제는 명시적 명령과 비상정지 입력 비활성이 모두 만족될 때만 허용한다.
- 위치 일관성(v0.2 개정): 하드웨어 게이트가 끊은 순간과 MCU가 타이머를 멈춘 순간 사이에 계수된 펄스는 실제로 나가지 않았을 수 있다. 기본안은 비상정지 발생 시 전 축 "위치 무효"(axis_status b11)로 두고 원점복귀를 요구한다(interface-spec §6, 파라미터 `estop_pos_policy`). 위치 유지가 필요하면 DC-08 선택지(게이트 앞 AND 게이트 + 계수)를 채택한다.
- 게이트 구현(v0.2): AM26C31 공통 enable(G, /G)[P8] 중 한 핀을 비활성 레벨로 고정하고 다른 핀을 비상정지 포토커플러 출력으로 직접 구동한다. 두 핀 조합 기능표는 데이터시트 대조 필요(미확인). 입력은 NC 접점·전류 상실 = 정지 측 [가정].
- 고지: 이 경로도 보조 정지이며 안전 회로를 대체하지 않는다(NFR-020). 기능안전 설계(이중화·진단 범위)는 v1 범위 밖이다(STD-004).
- 리밋·드라이브 알람 정지(FR-009, FR-011(a))는 해당 축만 정지하므로 1차 경로(전 축 차단)에 묶지 않고 MCU 경로로 처리한다. 하드웨어 차단까지 필요한지는 리밋 정지 시간 요구(Q14) 확정 후 판단한다.

### 2.7 전원

- 입력: 24 VDC ±10% [가정](NFR-007). 역접속 보호, 서지(TVS), 퓨즈 [가정: 산업 제어기 일반 구성. 규격 근거는 KC EMC 대상 여부(STD-001) 확인 후 보강].
- 로직 전원: 24 V → 강압 → 3.3 V 등(MCU·PHY 전압은 MCU 확정 후).
- 절연 전원 대안(DC-05)
  - PWR-A: 로직 전원은 24 V 입력에서 비절연 강압. 현장 I/O는 별도 현장 24 V로 구동하고 절연 소자로 로직과 분리.
  - PWR-B: 절연 DC-DC로 로직 측을 24 V 입력과 분리. 펄스 출력단까지 절연할 경우(DC-04 "절연") 출력단 전원도 절연 전원이 필요하다.
  - 원가·면적은 PWR-B가 크다(정성). NFR-009 해석(DC-04)에 따라 정한다.

| 구분 | 공통부 | 1축 모델 | 2축 모델 |
|---|---|---|---|
| PCB | 공용 PCB 1종 [추천, DC-07] | 축2 영역 부품 미실장 | 전체 실장 |

- 대안: 축 단위 모듈 보드(본체 + 축 보드 1~2장). 커넥터·조립 원가가 늘어 9만원 조건에서는 불리하다고 본다(정성, [가정]).
- (v0.2) 기구 제약: 하우징 후보 Phoenix ME MAX 22.5(폭 22.5 mm)[P17]에 2축 PCB·RJ45·6극 단자 6개(2축)가 수납되는지 미확인이다(BOM C6). 공용 PCB 1종 방침은 유지하되, 하우징 폭(22.5 mm급 / 45 mm급)과 단자 극 수는 DC-12에서 함께 정한다. 45 mm급 하우징 가격은 미확인이다.

## 3. 소프트웨어 블록(상위 수준)

모듈 분해·API는 다음 차수(modules/*.md)에서 정한다. 여기서는 실행 우선순위와 타이밍 경계만 정한다.

| 계층 | 블록 | 실행 문맥 | 마감·우선순위 |
|---|---|---|---|
| L0 하드웨어 | 펄스 타이머·카운터, 비상정지 게이트 | 하드웨어 | 펄스 타이밍은 CPU 무관 |
| L1 실시간 | 펄스 엔진(구간 갱신), 리밋·알람 정지, 비상정지 래치 | 최우선 인터럽트/DMA | 구간 갱신 마감 = 구간 길이(값 미확인). 플래시 쓰기 중에도 실행 가능해야 함(코드·데이터를 RAM에 배치, 해당 MCU의 제약 확인 필요) |
| L2 운동 | 운동 계획(가감속, 절대/상대, 원점복귀, JOG, 소프트 리밋), 축 상태기 | 상위 우선 태스크 | 구간 주기 이내에 다음 구간 계산 |
| L3 통신 | Modbus TCP 서버, Modbus RTU, 통신 두절 감시 | 일반 태스크 | NFR-010(미확인 ms) |
| L4 서비스 | 설정 저장, 진단·알람 이력, 펌웨어 갱신, PC 도구 지원 | 저우선 태스크 | 비실시간 |

- 원칙: L3·L4의 어떤 부하(최대 TCP 접속, 플래시 쓰기)도 L1 마감을 넘기게 해서는 안 된다. 이 원칙의 성립 여부가 §4의 실측 항목이다.

### 3.1 모듈 분해와 HAL 추상화 (v0.2)

MCU가 G3에서 바뀌어도(C1 STM32F407 ↔ C2 ESP32 ↔ C6 STM32H563) 상위 모듈을 그대로 쓰기 위해, MCU 의존 코드는 **HAL 계층(MOD-01~06)의 포트 구현**에만 둔다. 상위 모듈은 `hal_*.h` 공개 API와 OSAL(태스크·큐·뮤텍스·임계 구역)만 호출한다(DC-14).

```
 [PC/HMI 측]  MOD-21 pc_tool(Python) · MOD-22 test_automation(Python) · MOD-23~25 HMI 화면 데이터
                         │ Modbus TCP
 ┌───────────────────────┴───────────────────────────────────────────────────────────┐
 │ L3 통신    MOD-15 modbus_tcp   MOD-16 modbus_rtu(조건부)   MOD-17 fw_update          │
 │            MOD-14 modbus_core(레지스터 표: MOD-20 regmap_gen 생성)                    │
 │ L2·L4 응용 MOD-09 axis_control  MOD-10 estop_safety  MOD-11 io_manager               │
 │            MOD-12 param_store   MOD-13 alarm_diag    MOD-18 sequencer(권장)          │
 │ L1·L2 운동 MOD-08 motion_planner(순수 계산, 호스트 시험)  MOD-07 pulse_engine(구간 공급) │
 │ 시작      MOD-19 app_main(태스크 구성·모델 식별·워치독)                               │
 ├──────────────────────────── HAL 공개 API (MCU 무관) ───────────────────────────────┤
 │ MOD-01 hal_sys(OSAL·시간·WDT)  MOD-02 hal_pulse  MOD-03 hal_dio  MOD-04 hal_net      │
 │ MOD-05 hal_serial              MOD-06 hal_nvm                                        │
 ├──────────────── 포트 구현(교체 단위): port_stm32f4 / port_esp32 / (port_stm32h5) ─────┤
 │ STM32 HAL·LL + lwIP + FreeRTOS [가정]   |   ESP-IDF(RMT·PCNT·EMAC·lwIP·FreeRTOS)       │
 └───────────────────────────────────────────────────────────────────────────────────┘
```

- 핵심 불변식(모든 포트가 지켜야 함): `hal_pulse`는 큐에 들어온 구간의 펄스 수만큼만 출력하고, 다음 구간이 없으면 **추가 펄스 없이 정지**한다(언더런 = 정지, NFR-004). 이 불변식은 포트별 HIL 시험(MOD-22)으로 검증한다.
- RTOS: 두 계열 모두 FreeRTOS 사용 [가정](ESP-IDF는 FreeRTOS 기반, STM32는 FreeRTOS 포팅). OSAL은 얇은 래퍼만 둔다.
- 레지스터 맵 단일 원본: `regmap.yaml` → C 표(MOD-14), Python 모듈(MOD-21·22), 한국어 맵 문서(NFR-022), HMI 태그 목록(MOD-23~25). 수작업 이중 관리를 금지한다.
- 모듈별 책임·API·완료 기준은 modules/MOD-xx-*.md, 요구사항 추적은 handoff.md §6.

### 4.4 추천 근거와 위험

- 추천 근거(C1)
  1. 정지 시점을 하드웨어가 결정하므로 NFR-004(누락·추가 0)가 소프트웨어 지연에 묶이지 않는다(P4 원리, [S7] 기법). C2·C3는 각각 버퍼 보충 마감, 정지 인터럽트 응답이 NFR-004에 직결된다.
  2. 구간 방식 속도 갱신으로 CPU 부하가 펄스 주파수와 무관하다. 2축 × 200 kpps에서도 소프트웨어 마감은 구간 주기로 고정된다.
  3. 유선 이더넷 MAC이 내장되어 있어 추가 이더넷 칩 없이 PHY만 붙인다[S6].
  4. ESP32 기본형의 무선 기능은 v1에서 쓰지 않으므로(FR-017) 무선 탑재 이점이 없다.
- 프로젝트명(D-001)과의 관계: 프로젝트명에 ESP32가 들어 있으나 CON-001은 MCU를 전제하지 않는다. 추천이 STM32이므로 사용자 확인이 필요하다(DC-01). C2(ESP32 + RMT)가 실측에서 합격하고 원가가 유리하면 C2로 바꿀 수 있도록 G3 전 두 조합을 함께 실측한다.

## 8. 추천안과 결정 후보

### 8.1 추천안(1개)

**C1: STM32F407(내장 이더넷 MAC) + 축당 하드웨어 타이머 펄스 생성(PWM 타이머 + 슬레이브 계수 타이머 게이트, 구간 방식 속도 갱신) + RMII PHY 1포트 + 비상정지 하드웨어 게이트 + 공용 PCB(1축은 축2 미실장)·단일 펌웨어.**

- 200 kpps 근거 수준: 타이머 클록(168 MHz)·이더넷 MAC·N펄스/DMA 기법은 데이터시트·ST 응용 노트로 **확인**. "2축 동시 축당 ≥ 200 kpps + TCP 부하 중 누락 0"은 **미확인 → G3 전 실측 필요**(T-01~T-04). ESP32(C2)도 같은 조건으로 실측해 비교한 뒤 G3에서 확정한다.
- (v0.2) 원가: 추천 구성의 전자부품은 USD 약 16(2축)으로 원가의 승부처가 아니며, 2축 모델 9만원 초과 위험은 기구에서 온다(R-07, R-08). 원가만으로 C1을 바꿀 근거는 아직 없다. 단 기구 절감 후에도 초과하면 C2(약 USD −4.96)가 원가 측 대안이 되므로 C2 실측 비교를 유지한다.
- (v0.2) MCU 교체 대비: 상위 모듈은 HAL 추상화 뒤에 둔다(§3.1, DC-14). G3에서 C2로 바뀌면 MOD-01~06의 포트 구현만 새로 만든다.
