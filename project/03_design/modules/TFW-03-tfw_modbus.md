> servo1axis `movion_modbus_tcp.c`[E2]를 복사해 시험용으로 줄인 구현이다. W5500 경로는 제거한다(D-027). 레거시 창(HR 0~31, 코일 0~7, DI 0~7)은 기존 동작을 그대로 두어 기존 HMI(MT8051iP)로 축1을 운전할 수 있게 하고(T-14, 실사용 클라이언트 부하), 시험 창(0x7000~0x70FF, TFW-01)을 추가한다.

## 1. 책임 (이 모듈이 하는 일 / 하지 않는 일)
- 한다: EMAC + IP101 초기화(PHY 주소 1, 리셋 GPIO51), 고정 IP 192.168.0.220/24, 포트 502, 유닛 1[E2][E5]. 연결별 태스크 서버(기존 구조). FC01/02/03/05/06/15/16 처리: 레거시 창은 기존 `process_request` 동작, 시험 창은 TFW-01로 위임. 계측: 접속 수, 요청 수, 요청 처리 시간 최대·분포(히스토그램 8구간 [가정]), 링크 다운 횟수.
- 하지 않는다: 제품 레지스터 맵(MOD-14·20), 통신두절 감시, RTU.

## 2. 의존성
- 사용: ESP-IDF esp_eth·esp_netif·lwIP, TFW-01(시험 창), TFW-02(레거시 START → 축1 이동).
- 사용하는 쪽: TFW-01(시작), TFW-05(클라이언트).

## 4. 제약 조건
- 태스크 우선순위: 기존 서버 5, 연결 6[E2]. TFW-02 갱신 콜백(하드웨어 타이머 ISR)보다 낮다. 코어 배치는 TFW-01 cfg_flags b1.
- 최대 접속 수 = 빌드 설정 `TFW_MAX_CLIENTS`, 기본 4 [가정](기존 backlog 4). 접속 수에는 제어 연결(TFW-05)·부하 클라이언트·HMI를 **모두 포함**한다. 상한을 넘는 접속은 accept 후 즉시 닫는다(구현 방식, notes §8 C-03).
- T-05용 빌드는 `TFW_MAX_CLIENTS` ≥ 6(제어 1 + 부하 4 + HMI 1, architecture §6.1 T-05)으로 따로 만든다. 기본 4 빌드에서 T-05를 돌리면 판정은 FAIL이다(TFW-05 판정 규칙). 이 조건은 결정 후보 DC-19(architecture §8.2)의 권고안 기준이며, DC-19가 (b)로 확정되면 T-05 빌드값은 4, 부하 수는 2로 바뀐다.
- 레거시 창의 운전 결과·현재값은 축1 TFW-02 값에서 채운다(기존 `motion_task` 로직 축소 복사).

## 5. 완료 기준 (각 항목은 단위 테스트로 검증 가능해야 함)

|---|---|---|

## 6. 미확인·가정
- 히스토그램 구간·최대 접속 기본 4 [가정]. `TFW_MAX_CLIENTS`의 상한(lwIP 소켓 수·연결 태스크 메모리로 정해짐)은 미확인 — T-05 빌드에서 6 이상이 실제로 동작하는지 HIL로 확인한다.
- 제품 `max_clients`(0x0114) 기본값과 HMI 포함 여부는 DC-19·SRS Q26(동시 접속 수) 확정에 따른다.

## 7. 이슈 제기
1. (02_requirements / 사용자) NFR-023 동시 접속 수가 미확인이라 T-05 접속 수와 제품 기본 `max_clients`의 근거가 없다. Q26 답변 필요(DC-19).
- MT8051iP의 요청 주기·동시 연결 수는 미확인(실측 시 mb_req_count로 추정).
