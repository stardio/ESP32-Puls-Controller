# 설계→코딩 인터페이스: tfw_modbus (G3 전 시험 펌웨어 — IP101 Modbus TCP 서버)

| 모듈 ID | 버전 | 작성 | 대상 언어/플랫폼 | 추적 SRS ID |
|---|---|---|---|---|
| TFW-03 | 0.1 | architect | C(ESP-IDF 5.5.3, ESP32-P4, 내장 EMAC + IP101) | NFR-003, NFR-010, NFR-023, FR-022, T-05, T-14 |

> servo1axis `movion_modbus_tcp.c`[E2]를 복사해 시험용으로 줄인 구현이다. W5500 경로는 제거한다(D-027). 레거시 창(HR 0~31, 코일 0~7, DI 0~7)은 기존 동작을 그대로 두어 기존 HMI(MT8051iP)로 축1을 운전할 수 있게 하고(T-14, 실사용 클라이언트 부하), 시험 창(0x7000~0x70FF, TFW-01)을 추가한다.

## 1. 책임 (이 모듈이 하는 일 / 하지 않는 일)
- 한다: EMAC + IP101 초기화(PHY 주소 1, 리셋 GPIO51), 고정 IP 192.168.0.220/24, 포트 502, 유닛 1[E2][E5]. 연결별 태스크 서버(기존 구조). FC01/02/03/05/06/15/16 처리: 레거시 창은 기존 `process_request` 동작, 시험 창은 TFW-01로 위임. 계측: 접속 수, 요청 수, 요청 처리 시간 최대·분포(히스토그램 8구간 [가정]), 링크 다운 횟수.
- 하지 않는다: 제품 레지스터 맵(MOD-14·20), 통신두절 감시, RTU.

## 2. 의존성
- 사용: ESP-IDF esp_eth·esp_netif·lwIP, TFW-01(시험 창), TFW-02(레거시 START → 축1 이동).
- 사용하는 쪽: TFW-01(시작), TFW-05(클라이언트).

## 3. 입출력 정의
| 구분 | 이름 | 타입/단위 | 범위 | 설명 |
|---|---|---|---|---|
| 입력 | 레거시 창 | interface-spec §5.0.1 | | 기존과 같음. **운전 중 NVS 저장은 시험 설정으로 on/off**(기존: 쓰기마다 저장[E2], T-06 비교용) |
| 입력 | 시험 창 | TFW-01 §3 | | |
| 출력 | 0x7050 | mb_clients | U16 | 현재 접속 수 |
| 출력 | 0x7051 | mb_link_down_count | U16 | |
| 출력 | 0x7052 | mb_req_count | U32 | |
| 출력 | 0x7054 | mb_proc_max_us | U32 | 요청 처리 최대 시간(수신 완료 → 송신 시작) |
| 출력 | 0x7056~0x705D | mb_proc_hist[8] | U16 | 처리 시간 히스토그램 [가정 구간: <50, <100, <200, <500, <1k, <2k, <5k, ≥5k µs] |
| 오류 | 예외 응답 | | 01/02/03/0B | 기존 동작 |

공개 API(시그니처 수준):
```c
esp_err_t tfw_modbus_start(const uint8_t ip[4], uint16_t port, uint8_t unit_id, uint8_t max_clients);
void      tfw_modbus_get_stats(tfw_mb_stats_t *out);
```

## 4. 제약 조건
- 태스크 우선순위: 기존 서버 5, 연결 6[E2]. TFW-02 갱신 콜백(하드웨어 타이머 ISR)보다 낮다. 코어 배치는 TFW-01 cfg_flags b1.
- 최대 접속 4 [가정](기존 backlog 4). 5번째 접속은 닫는다.
- 레거시 창의 운전 결과·현재값은 축1 TFW-02 값에서 채운다(기존 `motion_task` 로직 축소 복사).

## 5. 완료 기준 (각 항목은 단위 테스트로 검증 가능해야 함)
| # | 기준 | 검증 방법 |
|---|---|---|
| 1 | MT8051iP 기존 프로젝트로 축1 Position·Speed 설정, START, Force Stop, 방향, 상태 표시 동작 | HIL(시연) |
| 2 | Python 클라이언트 4개 동시 FC03 125레지스터 연속 + FC16 쓰기 중 응답 정상, 통계 기록 | HIL(T-05, TFW-05) |
| 3 | 케이블 분리·재연결 후 서버 복구, link_down_count 증가 | HIL |
| 4 | 5번째 접속 거부 | HIL |

## 6. 미확인·가정
- 히스토그램 구간·최대 접속 4 [가정].
- MT8051iP의 요청 주기·동시 연결 수는 미확인(실측 시 mb_req_count로 추정).
